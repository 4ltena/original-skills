# Repository documentation

Read only when drafting a README or public repository docs. First inspect existing language, file division, headings and badge conventions. Do not replace them wholesale without a request.

- Make a public document understandable without private project history. Rework needed facts instead of copying `.project-notes/` or other private records. Remove secrets, local paths, usernames and host identifiers. This guidance grants no permission to publish or commit.
- Provide Japanese and English versions when requested or established by the repository. Without that policy, keep a short document together; split into `README.md` and `README.en.md` only when navigation benefits. Do not offer a language switch that leads to untranslated content.
- Use Mermaid when a diagram helps and the destination supports it. Do not add a diagram when prose suffices. Preserve existing diagram conventions.
- Use badges only for information that can be maintained, keeping the repository's established order. For new conventions, choose only needed version, license, environment or language badges, and make version claims follow the actual version. Put title and overview after badges.
- Unless specified otherwise, write a new repository's GitHub About description and topics in English.
