# Write for the reader

Use for a new request, guide, report, proposal, explanation, README or other persistent document. Work backward from what the reader must understand, decide or do. Do not load this Skill for a short conversational answer, an existing-text rewrite or a review-only request.

## Establish the material and outcome

- Identify the format, destination, audience, reading situation and required decision or action. Honor requested structure, length and terminology.
- Separate required content, available sources and information that must stay private. Ground numbers, names, quotations, dates and links in the supplied material. Do not invent experiences or facts. Distinguish observation, inference, plan and unknown.
- For a README or public repository documentation, read [repository documentation](references/repository-docs.md) only when that mode applies.
- For a persistent Japanese document, use `document-style-ja` as a companion after drafting. The companion owns Japanese fluency, wording and register checks. Do not load it for non-Japanese prose, ordinary chat or merely placing an unchanged quotation.

## Arrange content for its purpose

For **action-oriented writing**, put the needed action or conclusion where the reader can find it first. Place prerequisites, scope and irreversible effects before the action. Number multiple steps and pair each action with a way to check it. For a handoff, distinguish completed work, remaining work and the next owner or action. Give a specific time estimate only when supported.

For **explanation or argument**, connect the question, evidence, interpretation and conclusion. Compare on the same basis and state what a recommendation depends on.

Use headings that name their content and give each paragraph a clear point. Use a table when it improves comparison. In a continuing exchange, briefly restore the relevant state instead of assuming the reader remembers an earlier turn. Brevity must not remove a condition, exception or reason needed for a decision.

## Reduce reading effort

- Let the opening expose the main answer, request or action when the document's purpose permits. Put essential context beside it and optional background later; preserve a requested narrative or argumentative buildup.
- Use familiar words, concrete actors and actions. Explain an unfamiliar term where it is first needed. Keep each paragraph focused and each procedural step a bounded action, with prerequisites visible where used.
- Remove empty openings, repeated conclusions and side issues that do not serve the reader's purpose. Group long lists by meaning when useful; do not impose fixed item or sentence limits, hide required material or replace an explanation with a slogan.

## Finish against the sources

Compare the draft with the request and its sources. Check required content, claim support, numbers, quotations, references and private information. Read the opening and headings on their own to check that the reader can locate the main point or action. Do not call a command or link verified unless actually checked. If generating a PDF or other rendered artifact, inspect the available final artifact and report the scope of that inspection.
